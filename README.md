# mind-atlas ── こころの地図

燻太さんと大河が、読んだ本から拾った **用語・人物・実験・理論** をつないでいく地図。
1つの用語が1つのファイルになっていて、`links` でつなぐと地図の上に線が引かれる。

公開URL： https://winforest1129-sys.github.io/mind-atlas/

---

## 運用のながれ

1. **本を読む** → 表紙と奥付を撮って共有 → `心理学/蔵書リスト.md` と `読書メモ/` に登録
2. **気になった用語を大河に伝える**
3. **大河が調べる** → `nodes/用語.md` を作り、`## 調べたこと` を書く
4. **地図に登録** → `python tools/build_map.py` → `data.json` が更新される
5. **燻太さんが `## 燻太さんの考え` を書く**
6. **次の本へ** → 1に戻る。用語が既にあれば `links` を足すだけで、本と本がつながる

この6番目が肝。**別の本で同じ用語に出会ったとき、地図の上で線がつながる**。
本単位のメモだけでは起きないことが、ここで起きる。

## ノードの書きかた

`nodes/` に1用語1ファイル。ファイル名がそのまま用語名になる（`label:` で上書きできる）。

```markdown
---
type: 用語            # 用語 / 人物 / 実験 / 症例 / 書物 / 理論 / 予感
label: 中核意識        # 省略可。省略するとファイル名を使う
出典: 01_ダマシオ      # 蔵書リストの番号。カンマ区切りで複数可
確度: 推測            # 確認済（出典必須） / 推測 / 未調査
所持: 無              # 書物のときだけ。有 / 無 / 不明（既定）
入手:                 # 所持が「無」のときに書く。買える場所
  - {店: Amazon.co.jp, url: https://www.amazon.co.jp/dp/400029699X, note: ISBN-10 から}
links:
  - {to: 原自己, rel: 土台}
  - {to: 構成主義的情動理論, rel: 対立}
  - {to: 外向性, rel: 第I因子, 強さ: 強}   # 強さは省略可（既定は 標準）
refs:
  - {title: 論文や記事の題, url: https://..., note: 何を確かめたか}
---
## 調べたこと
（大河が書く。推測と確認済みを混ぜない）

## 燻太さんの考え
（燻太さんが書く）
```

### refs（引用元）について

- **実際に当たった外部の情報源だけを書く。** 右パネルのいちばん下にリンクとして出る。
- **空でいい。** 空なら「外部の情報源には当たっていない。大河の記憶による」と正直に表示される。
  埋めることより、**記憶で書いたものを記憶だと分かるようにしておくこと**のほうが大事。
- `確度: 確認済` なのに refs が空だと、ビルドが警告を出す（書物と人物は除く）。
  出典を書くか、`推測` に落とすかのどちらか。
- ビルドの最後に「引用元つき N / M」が出る。**記憶で書かれた分がいくつ残っているかが毎回見える。**

### 説明欄（右パネル）の幅

**地図と説明欄のあいだのつまみを、左右にドラッグすると幅が変わる。**

- **ダブルクリックで既定（330px）にもどる。**
- 幅は**そのブラウザに覚えさせている**（`localStorage` の `mindatlas.sideW`）ので、次に開いても同じ幅。
- 下限260px、上限は画面幅の72%。窓を小さくすると自動で収まる。
- ⚠ **スマホでは効かない**（下からせり上がるシートになるので、幅の概念が無い）。

### 所持 と 入手（まだ買っていない本）

**読みたくなったときに、その場で買えるようにしておくための欄。**

- `所持: 無` を書くと、右パネルの**いちばん上**に「**まだ手元に無い**」の枠が出て、`入手:` のリンクが並ぶ。
  読んでいる途中で「これが要る」と気づいた本を、**探し直さずに買える**。
- `入手:` の書式は `- {店: 店の名前, url: https://..., note: 補足}`。
  ⚠ **refs（引用元）とは別物**。refs は「大河が実際に当たった情報源」、入手は「買える場所」。
  混ぜると、出典の欄に買い物リンクが紛れて、この地図のいちばん大事な線引きが濁る。
- **`所持: 無` なのに `入手:` が空だと、ビルドが警告を出す。** 逆に、入手があるのに所持が「無」でなくても警告。
- Amazon.co.jp のURLは **`https://www.amazon.co.jp/dp/<ISBN-10>`** で作れる。
  ⚠ ISBN-13 しか分からないときは**チェックディジットを計算し直す**こと
  （例 978-4-00-029699-1 → `400029699X`。末尾が `X` になることがある）。作ったら**実際に開いて確認する**。

### 予感 という型（2026-08-31に追加）

**燻太さんが「関連がありそう」と感じたところから生まれた項目。** 地図では**星形**で出る。

- ⚠ **これは主張ではない。** まだ誰も確かめていない結びつきを、
  **筋の通るところ／切れるところ／方法論の罠／科学的に扱える版**の順に並べて置いておくための型。
- 確度は原則 `推測`。⭐ **本文で「どこが大河の見立てで、どこが出典つきか」を必ず分ける。**
- ⚠ **予感を育てるときは、まず〈通っていないところ〉を書く。**
  面白い符合ほど、都合のいい部分だけ集めやすい。

### 強さ（線の重みづけ）

**`強さ: 強 / 標準 / 弱`。省略すると 標準。**
親と子のような**直接的なつながり**を `強` にすると、レイアウトで**子が親の近くに寄る**。

- 仕組みは「ばね」。強い線ほど**短く・硬い**ばねになる。
  対応表は `index.html` の **`PULL`** ひとつだけ（`len`＝ばねの自然長、`elas`＝硬さ）。**調整はここだけ触る。**
- 見た目でも太さが変わる（強 2.0 ／ 標準 1.3 ／ 弱 0.9 の破線）。
  ⚠ ただし **`対立`・`批判` の赤はそのあとに来るので、赤が優先されたまま**。
- ⚠⚠ **`len` を小さくしすぎると団子になって名前が読めなくなる。**
  重なりの歯止めは `nodeSeparation` と `nodeDimensionsIncludeLabels` のほうなので、
  強さを増やしたら**この2つも合わせて上げる**こと。
- ビルドの最後に「線の強さ: 強 N 本 ／ 弱 N 本」が出る。

**いま `強` にしてあるのは、親とその構成要素にあたる14本だけ**
（`ビッグファイブ`→5因子／`HEXACO`→6因子／`ダーク・トライアド`→3要素）。

- **`rel` に「対立」か「批判」が入ると、線が赤くなる。** どこで論争が起きているかが地図で見える。
- **`脳部位:` を書くと、右パネルに脳の模式図が出て、その領域が光る。**
  使えるIDは `tools/build_map.py` の `BRAIN_AREAS`（前頭前野 pfc／腹内側前頭前野 vmpfc／
  眼窩前頭皮質 ofc／背外側前頭前野 dlpfc／一次運動野 motor／体性感覚野 somatosensory／
  頭頂葉 parietal／後頭葉 occipital／側頭葉 temporal／島皮質 insula／前部帯状回 acc／
  後部帯状回 pcc／脳梁 corpus_callosum／扁桃体 amygdala／海馬 hippocampus／視床 thalamus／
  視床下部 hypothalamus／脳幹 brainstem／小脳 cerebellum）。カンマ区切りで複数可。
  知らないIDを書くとビルドが警告を出す。
- **`to` の用語がまだ無くてもいい。** 灰色の破線で「これから調べる」として地図に出る。
  消さずに残すと、**次に何を調べるかが地図の上に見えている**状態になる。
- 見出し（`## 〇〇`）は自由に足せる。そのまま右のパネルに出る。

## 画面の見かた

**左＝一覧パネル**（ヘッダーの「一覧」で開け閉め）
- **本でしぼる** … 本ごとのチェックを外すと、**その本〈だけ〉から派生したノードと線**が消える。
  複数の本にまたがる用語（例：ソマティック・マーカー仮説）は、どれか1冊でも表示中なら残る。
  **本と本をつなぐ橋を切らないため。** 出典を持たない概念と「これから調べる」は常に残る。
- **型ごとの一覧** … 書物／人物／理論／症例／実験／用語ごとの並び。クリックでその用語へ飛ぶ。
  **「記憶」の印**が付いているものは、外部の情報源に当たっていないノード。

**まんなか＝地図**。**右＝クリックした用語の中身**（本文 → 脳の図 → つながり → 引用元）。

### ⭐ ノードの位置（`positions.js`）

**2026-09-04 に、開くたびに配置が変わるのをやめた。**
前は力学レイアウト（fcose・`randomize:true`）を**開くたびに回していた**ので、
同じ地図なのに毎回ちがう形で出てきた（実測＝2回のあいだで最大 618px のずれ）。
地図は「どこに何があるか」を覚えて使うものなので、これがいちばん困る。

```bash
python tools/build_map.py         # 先にこちら
python tools/build_positions.py   # ⭐そのあとに、これ
```

`tools/build_positions.py` が**手元で1回だけ**レイアウトを回して、
座標を `positions.js`（`window.POS`）に固める。画面はそれを置くだけになる。

- ⚠ **毎回流さなくてよい。**ノードを足しただけなら、そのノードは
  **線でつながっている相手のそば**に置かれる。たくさん足したときや、
  配置が窮屈になってきたときに流し直す。
- ⚠ **`positions.js` が無くても地図は動く。**そのときは今までどおり力学レイアウトに倒れ、
  レイアウト欄も自動で「ネットワーク」に戻る。
- ⭐ **レイアウト欄で「ネットワーク」を選べば、その場で回し直せる**（保存はされない）。
- ⚠ 位置を作り直したのに古い配置が出るときは、**強い再読み込み（Ctrl+F5）**。
  `positions.js` は素の `src` で読んでいるので、キャッシュが残ることがある。

⚠ **コミットメッセージは英語で、引用符（`"` `'`）を使わない。**
PowerShell 5.1 が引数を割ってしまい `pathspec did not match` で落ちる（植物図鑑で3回やらかした）。

⚠ **`data.json` は生成物だが、git に入れる。** GitHub Pages が読むファイルだから。
ビルドを忘れて push すると、地図が古いままになる。

## 検索を「入力が落ち着いてから」に直した（2026-09-05）

**症状**：語を打っているあいだ絞り込みが並行して走り、
打ち終わったあとも地図がラグを引きずってカクついた。

**原因**：`oninput` が **1打鍵ごとに** `search()` を呼んでいた。
`search()` の中身は ①全要素の class 付け替え ②全ノードの走査
③**380ms の fit アニメーション**。とくに③が `cy.animate` の待ち行列に積み上がるので、
手を止めたあとも動き続けていた。

**直しかた（3つ）**

| | 何を | なぜ |
|---|---|---|
| ① | **デバウンス**（`SEARCH_WAIT = 250` ms） | 最後の入力から待って**1回だけ**走らせる |
| ② | **IME 対応**（`compositionstart`〜`compositionend`） | **日本語の変換中は走らせない** |
| ③ | **`cy.stop(true)`** を `spotlight()` の `cy.animate` の前に | **待ち行列ごと捨てる**。`cy.stop()` だけでは積まれたぶんが残る |

空にしたときは待たずにすぐ戻す／Enter は待たずに今すぐ走る。
待ち時間を変えたいときは `SEARCH_WAIT` だけ触ればよい。

### 実測（ヘッドレス Chrome）

日本語入力でいちばん効く。「協調性」を「きょうちょうせい」から変換して打つ道すじを再現した:

| | 打鍵 | 変換中に走った検索 | 合計 |
|---|---|---|---|
| **直す前** | 20 | **20回**（`きょうc`・`きょうちょうせi` のような途中の文字列で毎回） | 20 |
| **直したあと** | 20 | **0回** | **1回**（`協調性` のみ） |

結果は変わらず（`1件（完全一致） ／ つながり 6件`）、JS エラー 0。
確かめたこと＝①打った直後は走らない／待てば当たる ②Enter は待たずに走る
③空にしたら待たずに戻る。

### 測るときの落とし穴

- **デバウンスを入れたあとは、打ち終わってすぐ測ると「何も起きていない」。**
  `settle=20ms` と出て直った気になる。`search` が走るのを待ってから測ること。
- **ヘッドレスの仮想時間では `performance.now()` も rAF も進まない。**
  だからアニメの落ち着き時間は測れない（`cy.animated()` が真のまま残る）。
  当てになるのは「`search()` が何回走ったか」のほう。
- **このページは `file://` では測れない**（`fetch('data.json')` が CORS で弾かれる）。
  `python -m http.server` を立てて `http://127.0.0.1:...` で開く。
